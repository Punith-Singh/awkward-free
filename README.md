# Awkward-Free

A native Android app for making informal payment reminders a little less awkward. Built with Kotlin and Jetpack Compose for friends and roommates.

## Features

- Dashboard, all dues, add/edit due, due details, settled tabs and payment settings.
- Instagram-inspired bottom navigation and the violet/indigo V2 design.
- Friendly, playful and direct messages that can be edited before opening WhatsApp.
- Optional WhatsApp number and UPI ID; reminders contain a UPI payment URI and the ID as a fallback.
- Manual settlement and reopen actions, delete confirmation, and the time WhatsApp was opened for a reminder.
- Record partial payments; outstanding balances and UPI links use the remaining amount.
- Optional daily on-device due-date reminders, sent only to you.
- Versioned local JSON backup export and confirmed restore via the Android file picker.
- On-device storage; existing entries from the original version are preserved.

The app does not send messages automatically, confirm WhatsApp delivery, process payments, or verify a UPI transfer. Confirm payment before marking a tab settled. UPI link handling depends on the recipient's messaging and payment apps. Data is local to the device and is removed if app data is cleared or the app is uninstalled.

## Build

Open in Android Studio with Android SDK 35 and JDK 17. The repository currently has no Gradle wrapper: with Gradle 8.9 installed, run `gradle wrapper --gradle-version 8.9`, then sync and run the `app` configuration on Android 8.0 or newer. GitHub Actions also builds the debug app using Gradle 8.9.

Plus Jakarta Sans, the typeface used in the Figma design, is bundled under the SIL Open Font License; see `licenses/PlusJakartaSans-OFL.txt`.

## Code structure

The Kotlin source is organized under `app/src/main/java/com/punith/awkwardfree/`:

- `ui/screens/` — Home, dues, add/edit, details, nudge, settled and settings screens.
- `ui/components/` — reusable UI elements, such as due cards and buttons.
- `ui/theme/` — colours and typography.
- `navigation/` — screen routing, app state and bottom navigation.
- `model/` — the `Due` data class.
- `data/` — local SharedPreferences storage.
- `util/` — formatting, reminder messages and UPI links.

`MainActivity.kt` sets up the app theme and launches the Compose UI. This remains a lightweight Compose state-based architecture; it does not use ViewModels or Room yet.

## Reminders and backups

Enable due-date reminders in Settings. Android may delay the approximately 9 AM notification; it summarizes tabs due tomorrow, today or overdue without sending WhatsApp messages. Android 13+ requires notification permission.

Settings can export a JSON backup or restore one after confirmation. Restore replaces the current dues, name and UPI ID; it does not change your reminder setting. Backup files include personal and financial details, so store them privately.

## Firebase email sign-in (setup required)

This branch adds optional Google and email/password authentication. Firebase Authentication manages credentials; passwords are not saved by the app. Each signed-in account has separate device-only records. Guest records remain intact but are not migrated to an account automatically. **Cloud Firestore sync is not implemented**, so signing in alone does not move or sync dues between devices. Keep the existing export/restore backup for device transfers.

To configure authentication:

1. Create or select a Firebase project. Register an Android app with package name `com.punith.awkwardfree`.
2. Enable **Email/Password** in Firebase Authentication → Sign-in method.
3. Download the Firebase-generated `google-services.json` for that Android app and place it at `app/google-services.json` locally. The file is ignored by Git in this repository; do not commit service-account credentials.
4. Rebuild the app. Without the file, the app remains usable in device-only mode and Settings shows that account setup is needed.
5. For Google sign-in, add the signing certificate SHA-1 for every signing key you will use (debug, release and Play App Signing where applicable) in Firebase project settings, enable Google under Authentication → Sign-in method, then download an updated `google-services.json`. The file must contain the OAuth web client generated by Firebase.
6. Open Settings → Sign in or create account. After sign-in, the account's local data is separate from the guest data. The user's account can sign out through the same screen.

Google and email/password sign-in and password reset require an internet connection and a real configured Firebase project. Google sign-in additionally needs supported Google Play services, the right signing SHA-1 and an updated OAuth-enabled configuration. Configure email handling and Firebase security settings for your deployment. No production Firebase project or credentials are included.

### Google sign-in

The account screen offers **Continue with Google** using Android Credential Manager and exchanges the Google ID token with Firebase Authentication. It keeps Firebase credentials out of app data and clears the Credential Manager state on sign-out.

Enable Google in Firebase Authentication, add each Android signing certificate SHA-1 (including debug, release and the Play App Signing key where applicable), and download a fresh `google-services.json` with the OAuth web client. Replace the local file in `app/` and rebuild. A missing Google web client is reported in the app. A real Google sign-in requires a configured Firebase project and a device or emulator with Google Play services. This does not implement Firestore sync.
